The diagram shows the σ choice of the code (σ = 1/10, for numbers above 16 bits σ = 1/15). With each of these values all number types are factorized in the same way, because order finding determines the result.

🔬 Overview (library version 2.1)

The diagram shows the flow of the two Python libraries: on the left order finding in factorization_benchmark_library.py, on the right the harmonic classification in optimized_harmonic_lib.py. Order finding assigns a σ value to each number category; it determines the category by trial division, which already factorizes N (R63).

🎯 Key Features (Version 2.1)

One σ value for almost all categories: σ = 1/10, above 16 bits σ = 1/15. Every σ for which the threshold 1/1000 does not apply gives the same result; very small values such as 1/1000 or 4/30000 reject periods and lower the hit rate (R63).

Categorization: twin, cousin, near and distant prime pairs; it presupposes the factors (R63).

Special cases: 1729, 2047 and 4181 get a category of their own with the same σ.

GCD check: common divisors with 2, 3, 5, 7 are caught before the period search.

⚡ Runtime and Success

Success: of 20 semiprimes between 15 and 19043 the library factorizes 19, 5 of them already via the gcd with a base; the result is the same for σ = 1/10, 1/15 and 1/100 (R63).

Runtime: in the range used, σ changes neither result nor runtime (R63).

Larger numbers: the period search stops at r < 2000. Numbers whose orders for all bases 2, 3, 5, 7 lie above this are not factorized; of 45 semiprimes with 8 to 32 bits the library factorizes 23.
