⚡ Ordnungssuche (Periodenfindung)

Faktorisierung über die Ordnung von a modulo N, wie im klassischen Teil von Shors Algorithmus

Das Prinzip
Gesucht ist die Ordnung r von a modulo N, also das kleinste r mit a^r ≡ 1 (mod N). Ist r gerade und a^(r/2) ≢ −1 (mod N), liefert ggT(a^(r/2) ± 1, N) einen echten Teiler von N. Das ist der klassische Teil von Shors Algorithmus; ein davon unterscheidbares T0-Verfahren gibt es nicht (R65).

🧠 Grundgedanken der Implementierung

1
Exakte Brüche
Die Bewertung rechnet mit Python-Fraction: σ als Bruch (z. B. 1/10), π als 355/113. Dadurch ist sie auf jeder Plattform bitgenau reproduzierbar (R65).
2
N als Bezugsgröße
Die Darstellung schreibt Faktoren als Anteile p/N und q/N. An der Rechnung ändert das nichts; sie arbeitet mit ganzen Zahlen modulo N.
3
Periodenbewertung
Jede Periode r erhält die Bewertung 1/(1 + (ω−π)²/(4σ)) mit ω = 2π/r. Sie fällt für r > 2 streng monoton und kann die Wahl der Ordnung nicht verschieben (R63).

⚙️ Rasterparameter σ

Die Python-Bibliothek rsa/factorization_benchmark_library.py ordnet jeder Zahlkategorie einen σ-Wert zu (im Code heißt er xi). Er ist nicht der FFGFT-Parameter ξ = 4/30000 (R75). Die Kategorie bestimmt der Code per Probedivision bis 1000; damit ist N bei allen Testzahlen schon zerlegt, bevor σ gewählt wird (R63).

🧮 Mathematische Formulierung

Bewertung im Python-Code (Lorentzform, ohne Einfluss auf das Ergebnis, R63):
R(r) = 1/(1 + (ω−π)²/(4σ)),   ω = 2π/r
Bewertung in den HTML-Werkzeugen unter 2/html/ (Gaußform):
R(r) = exp(−(ω−π)²/(4σ))
Beide Formen haben ihr Maximum bei r = 2 und fallen für größere r streng monoton; die Ordnung wählen sie nicht aus (R63).
def _calculate_resonance_with_optimized_xi(self, r, xi): # xi ist der Rasterparameter σ, nicht das FFGFT-ξ (R75) omega = Fraction(2, 1) * self.pi_fraction / Fraction(r, 1) # ω = 2π/r, π ≈ 355/113 diff = omega - self.pi_fraction diff_squared = diff * diff denominator = Fraction(4, 1) * xi exponent = -diff_squared / denominator score = Fraction(1, 1) / (Fraction(1, 1) + abs(exponent)) return score # Verwendung: Die erste Periode r mit a^r ≡ 1 (mod N) wird angenommen, # sobald score > 1/1000 ist; bei σ = 1/10 gilt das für jedes r (R63).

🎵 Musikalische Benennung der Faktorverhältnisse

Das Verhältnis der gefundenen Faktoren lässt sich musikalisch benennen (siehe Harmonische Klassifikation); für die Ordnungssuche spielt es keine Rolle:

  • Reine Quinte (3:2) → p/q ≈ 1.5
  • Große Terz (5:4) → p/q ≈ 1.25
  • Goldenes Verhältnis (φ:1) → p/q ≈ 1.618
  • Tritonus (√2:1) → p/q ≈ 1.414

🔧 Warum der Code mit Brüchen rechnet

Reproduzierbarkeit der Bewertung

Gleitkommarechnung rundet in jedem Schritt; die letzten Stellen einer Bewertung können von Plattform und Mathematikbibliothek abhängen. Mit Fraction rechnet der Code ohne Rundung:

# Gleitkomma: Rundung in jedem Rechenschritt bewertung = 1 / (1 + (2*math.pi/r - math.pi)**2 / (4*0.1)) # Fraction: exakte Brüche, bitgenau reproduzierbar pi = Fraction(355, 113) bewertung = 1 / (1 + (2*pi/r - pi)**2 / (4*Fraction(1, 10)))

Reproduzierbarkeit: Die Bewertung ist mit Fraction auf jeder Hardware bitgenau gleich (R65). π selbst ist dabei durch 355/113 angenähert. Auf die gefundenen Faktoren hat das keinen Einfluss, denn die Ordnungssuche rechnet ohnehin ganzzahlig.

🎯 Fazit

Der Kern
Die Faktoren liefert die Ordnungssuche aus elementarer Zahlentheorie: Satz von Euler und ggT-Extraktion wie bei Shor.

Bewertung und Bruchrechnung machen die Ausgabe reproduzierbar, ändern aber das Ergebnis nicht (R63).

Ein FFGFT-eigenes Faktorisierungsverfahren ist das nicht (R65).
