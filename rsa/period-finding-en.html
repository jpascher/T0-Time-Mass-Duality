⚡ Order Finding (Period Finding)

Factorization via the order of a modulo N, as in the classical part of Shor's algorithm

The Principle
We look for the order r of a modulo N, i.e. the smallest r with a^r ≡ 1 (mod N). If r is even and a^(r/2) ≢ −1 (mod N), gcd(a^(r/2) ± 1, N) yields a proper divisor of N. This is the classical part of Shor's algorithm; a distinguishable T0 method does not exist (R65).

🧠 Ideas behind the implementation

1
Exact fractions
The scoring uses Python's Fraction: σ as a fraction (e.g. 1/10), π as 355/113. This makes it bit-for-bit reproducible on every platform (R65).
2
N as reference
The presentation writes factors as shares p/N and q/N. This changes nothing in the computation, which works with integers modulo N.
3
Period scoring
Each period r receives the score 1/(1 + (ω−π)²/(4σ)) with ω = 2π/r. It decreases strictly for r > 2 and cannot shift the choice of the order (R63).

⚙️ Grid parameter σ

The Python library rsa/factorization_benchmark_library.py assigns a σ value to each number category (in the code it is called xi). It is not the FFGFT parameter ξ = 4/30000 (R75). The code determines the category by trial division up to 1000; for all test numbers N is therefore already factorized before σ is chosen (R63).

Recomputed with the library on 20 semiprimes from 15 to 19043: σ = 1/10, 1/15, 1/42, 1/50, 1/100 and 10⁶ give the same 19 factorizations. σ = 1/1000 and σ = 4/30000 give only 5, all of them from the gcd with one of the bases 2, 3, 5, 7. In the range used the scoring therefore does not filter; where it filters, it lowers the hit rate (R63).

🧮 Mathematical Formulation

Scoring in the Python code (Lorentzian form, no effect on the result, R63):
R(r) = 1/(1 + (ω−π)²/(4σ)),   ω = 2π/r
Scoring in the HTML tools under 2/html/ (Gaussian form):
R(r) = exp(−(ω−π)²/(4σ))
Both forms peak at r = 2 and decrease strictly for larger r; they do not select the order (R63).
def _calculate_resonance_with_optimized_xi(self, r, xi): # xi is the grid parameter σ, not the FFGFT ξ (R75) omega = Fraction(2, 1) * self.pi_fraction / Fraction(r, 1) # ω = 2π/r, π ≈ 355/113 diff = omega - self.pi_fraction diff_squared = diff * diff denominator = Fraction(4, 1) * xi exponent = -diff_squared / denominator score = Fraction(1, 1) / (Fraction(1, 1) + abs(exponent)) return score # Use: the first period r with a^r ≡ 1 (mod N) is accepted # as soon as score > 1/1000; for σ = 1/10 this holds for every r (R63).

🎵 Musical Naming of Factor Ratios

The ratio of the factors found can be named musically (see Harmonic Classification); for order finding it plays no role:

  • Perfect Fifth (3:2) → p/q ≈ 1.5
  • Major Third (5:4) → p/q ≈ 1.25
  • Golden Ratio (φ:1) → p/q ≈ 1.618
  • Tritone (√2:1) → p/q ≈ 1.414

🔧 Why the Code Computes with Fractions

Reproducibility of the score

Floating-point arithmetic rounds at every step; the last digits of a score can depend on the platform and the maths library. With Fraction the code computes without rounding:

# Floating point: rounding at every step score = 1 / (1 + (2*math.pi/r - math.pi)**2 / (4*0.1)) # Fraction: exact fractions, bit-for-bit reproducible pi = Fraction(355, 113) score = 1 / (1 + (2*pi/r - pi)**2 / (4*Fraction(1, 10)))

Reproducibility: With Fraction the score is bit-for-bit identical on any hardware (R65). π itself is approximated by 355/113. This has no influence on the factors found, because order finding computes with integers anyway.

🎯 Conclusion

The Core
The factors come from order finding, i.e. from elementary number theory: Euler's theorem and gcd extraction as in Shor.

Scoring and fraction arithmetic make the output reproducible but do not change the result (R63).

This is not an FFGFT factorization method of its own (R65).
