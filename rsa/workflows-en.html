🔧 Algorithm Workflows

Step-by-step functionality of both approaches

⚡ Order Finding - Process

Overview

Order finding (period finding as in Shor) determines factors of composite numbers. The library rsa/factorization_benchmark_library.py has a grid parameter σ (called xi in the code); in the range used it has no effect on the result, and it is not the FFGFT parameter ξ (R63, R75).

Order Finding Process
  • 1
    Categorization and σ Choice
    The code factorizes N by trial division up to 1000, assigns it to a category (twin_prime, cousin_prime, etc.) and selects the corresponding σ value. The category thus already presupposes the factors; σ has no effect on the result (R63).
    xi_strategy = self._select_optimized_xi_strategy(n) xi_value = self.xi_profiles[xi_strategy]
  • 2
    Trivial Factor Check
    Check for common divisors with the small primes 2, 3, 5, 7 via gcd.
    for basis in [2, 3, 5, 7]: if math.gcd(basis, n) > 1: factor = math.gcd(basis, n) return [factor, n // factor]
  • 3
    Period Search with Scoring
    For each base a = 2, 3, 5, 7 the code looks for the first r < min(N, 2000) with a^r ≡ 1 (mod N), i.e. the order. For σ = 1/10 and 1/15 the score lies above the threshold 1/1000 for every r; the order is therefore always accepted (R63).
    for r in range(2, min(n, max_periods)): if pow(a, r, n) == 1: # period found resonance = self._calculate_resonance_with_optimized_xi(r, xi) if resonance > self.threshold: # threshold = 1/1000 return r
  • 4
    Factor Extraction
    If the order is even and a^(r/2) ≢ −1 (mod N), gcd(a^(r/2) ± 1, N) yields a proper divisor; otherwise the next base follows.
    x = pow(a, period // 2, n) f1 = math.gcd(x - 1, n) f2 = math.gcd(x + 1, n) if 1 < f1 < n: return [f1, n // f1]

σ Choice in Detail

Decision Logic (factors p, q from trial division)

IF |p - q| = 2, ≤ 6, ≤ 12 or larger (presupposes the factors sought, R63)
→ twin_prime, cousin_prime, near_twin_prime, distant_prime (σ = 1/10)
IF N ∈ {1729, 2047, 4181}
→ special_cases (σ = 1/10)
IF N has more than 16 bits
→ large_composite (σ = 1/15)
ELSE
→ universal (σ = 1/10)

🎼 Harmonic Classification - Process

Overview

The harmonic classification (rsa/optimized_harmonic_lib.py) first factorizes N by trial division and then names the ratio of the two factors with a musical interval. It uses a 4-level search with logarithmic octave reduction; it is not a factorization of its own (Doc. 343).

Harmonic Classification Process
  • 1
    Find Factors
    Classical factor search using trial division up to √n.
    for i in range(2, int(math.sqrt(n)) + 1): if n % i == 0: return (i, n // i)
  • 2
    Calculate Ratio and Octave Reduction
    The ratio max(factors)/min(factors) is calculated and reduced to the base octave.
    ratio = max(factors) / min(factors) while ratio >= 2.0: ratio /= 2.0 octave_shift += 1
  • 3
    Level Prediction
    From the larger of the two factors and the reduced ratio the code determines the level at which the level search starts; the higher of the two predictions applies.
    if max_prime <= 17: prime_level = 1 # BASIS elif max_prime <= 31: prime_level = 3 # COMPLEX else: prime_level = 4 # ULTRA if ratio >= 1.85: ratio_level = 4 elif ratio >= 1.60: ratio_level = 3 elif ratio >= 1.40: ratio_level = 2 else: ratio_level = 1 level = max(prime_level, ratio_level)
  • 4
    Hierarchical Harmony Search
    First the code checks a cache of frequent ratios and then searches all levels within the tolerance bounds. Only if this yields nothing does it search the levels one after another, starting with the predicted one; the tolerance grows per level by the factor 1.0 / 1.1 / 1.2 / 1.3.
    for level_idx in search_order: for ratio, interval in level.intervals: cents_deviation = abs(1200 * log2(target_ratio / ratio)) if cents_deviation <= tolerance * level.tolerance_factor: return SUCCESS(interval, cents_deviation)

Shares per level, recomputed on all 2624 semiprimes below 10 000 (±50 cents); they mainly follow the number of target ratios per level (10, 10, 15, 30):

BASIS (14.9 %)
Classical musical intervals from the primes 2, 3, 5: unison (1:1), fifth (3:2), fourth (4:3), major third (5:4), etc.
EXTENDED (17.9 %)
Jazz and modern harmonies: natural seventh (7:4), 11th harmonic (11:8), 13th harmonic (13:8), etc.
COMPLEX (21.4 %)
Spectral music and microtonal: 29:16, 31:16, 25:16, etc.
ULTRA (45.8 %)
Xenharmonic ratios: 37:32, 41:32, 61:32, etc.; most ratios of large prime factors end up here.

🔄 Optimizations in the Code

Bounds Filtering
Calculation of upper and lower bounds for valid ratios from the tolerance to reduce search time (harmonic library).
Cached Calculations
LRU cache for frequent octave reductions and logarithmic distance calculations using the @lru_cache decorator (harmonic library).
Search Order
The harmonic library starts with the predicted level. Order finding chooses σ by category; this does not change the result.
Rational Arithmetic
Order finding scores with Fraction and is therefore bit-for-bit reproducible (R65). The harmonic library computes cent distances in floating point.

🎯 Differences Between Approaches

Order Finding vs. Harmonic Classification

Order finding: Looks for the order of a modulo N and derives a divisor from it via the gcd; scoring with σ does not change the result.

Harmonic classification: Factorizes N by trial division and assigns the ratio of the factors to a musical interval.

When to Use Which Approach?

To factorize N:
→ Order finding (period finding as in Shor) or classical methods such as Pollard rho
To name the ratio of factors found:
→ Harmonic classification
For both:
→ Factorize first, then name
