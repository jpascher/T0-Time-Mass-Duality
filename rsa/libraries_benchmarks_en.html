🔬 Technical Details

# Rational arithmetic in order finding, floating point in the harmonic library import math from fractions import Fraction # Exact ratios instead of floating point numbers pi_exact = Fraction(355, 113) # π approximation sigma = Fraction(1, 10) # grid parameter σ (no effect on the result) # Order finding: period scoring with exact ratios def calculate_period_score(r, sigma): omega = Fraction(2) * pi_exact / Fraction(r) diff = omega - pi_exact score = Fraction(1) / (Fraction(1) + diff * diff / (4 * sigma)) return score # Harmonic: logarithmic cents calculation def calculate_cents_deviation(ratio1, ratio2): return abs(1200 * math.log2(float(ratio1 / ratio2)))

Why rational arithmetic?

  • Bit-for-bit reproducible scoring on any hardware (R65)
  • No rounding inside the fraction arithmetic; π itself is approximated by 355/113
  • No influence on the factors found: order finding computes with integers

🎯 Practical Usage

# Example: complete workflow with both approaches from t0_rational_optimized import T0RationalSimulatorOptimized from optimized_harmonic_lib import OptimizedHarmonicFactorizer def analyze_number(n): """Analyze a number with both approaches""" # Order finding t0 = T0RationalSimulatorOptimized(n) t0_result = {'factors': t0.shor_t0_rational() or None} # Harmonic classification (trial division, then naming) harmonic = OptimizedHarmonicFactorizer() harmonic_result = harmonic.factorize(n) print(f"Number: {n}") print(f"Order finding successful: {t0_result['factors'] is not None}") print(f"Harmonic assignment: {harmonic_result.success}") if harmonic_result.success: print(f"Musical interval: {harmonic_result.harmonic_name}") print(f"Hierarchy level: {harmonic_result.level_name}") return t0_result, harmonic_result # Test different number types test_numbers = [221, 323, 1643, 2491, 10403] for num in test_numbers: analyze_number(num) # Result: order finding factorizes 221, 323 and 1643; for 2491 and 10403 # it returns no factors. The harmonic library names all five.
