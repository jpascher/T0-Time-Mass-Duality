⚡ Ordnungssuche - Ablauf

Überblick

Die Ordnungssuche (Periodenfindung wie bei Shor) ermittelt Faktoren zusammengesetzter Zahlen. Die Bibliothek rsa/factorization_benchmark_library.py kennt einen Rasterparameter σ (im Code xi); er hat im verwendeten Bereich keinen Einfluss auf das Ergebnis und ist nicht der FFGFT-Parameter ξ (R63, R75).

Ablauf der Ordnungssuche
  • 1
    Kategorisierung und σ-Wahl
    Der Code zerlegt N per Probedivision bis 1000, ordnet es einer Kategorie zu (twin_prime, cousin_prime usw.) und wählt den zugehörigen σ-Wert. Die Kategorie setzt die Faktoren also schon voraus; σ hat keinen Einfluss auf das Ergebnis (R63).
    xi_strategy = self._select_optimized_xi_strategy(n) xi_value = self.xi_profiles[xi_strategy]
  • 2
    Triviale Faktor-Prüfung
    Überprüfung auf gemeinsame Teiler mit den kleinen Primzahlen 2, 3, 5, 7 mittels ggT.
    for basis in [2, 3, 5, 7]: if math.gcd(basis, n) > 1: factor = math.gcd(basis, n) return [factor, n // factor]
  • 3
    Periodensuche mit Bewertung
    Für jede Basis a = 2, 3, 5, 7 sucht der Code das erste r < min(N, 2000) mit a^r ≡ 1 (mod N), also die Ordnung. Die Bewertung mit σ liegt bei σ = 1/10 und 1/15 für jedes r über dem Schwellwert 1/1000; die Ordnung wird daher immer angenommen (R63).
    for r in range(2, min(n, max_periods)): if pow(a, r, n) == 1: # Periode gefunden resonance = self._calculate_resonance_with_optimized_xi(r, xi) if resonance > self.threshold: # threshold = 1/1000 return r
  • 4
    Faktor-Extraktion
    Ist die Ordnung gerade und a^(r/2) ≢ −1 (mod N), liefert ggT(a^(r/2) ± 1, N) einen echten Teiler; sonst folgt die nächste Basis.
    x = pow(a, period // 2, n) f1 = math.gcd(x - 1, n) f2 = math.gcd(x + 1, n) if 1 < f1 < n: return [f1, n // f1]

σ-Wahl im Detail

Entscheidungslogik (Faktoren p, q aus der Probedivision)

WENN |p - q| = 2, ≤ 6, ≤ 12 oder größer (setzt die gesuchten Faktoren voraus, R63)
→ twin_prime, cousin_prime, near_twin_prime, distant_prime (σ = 1/10)
WENN N ∈ {1729, 2047, 4181}
→ special_cases (σ = 1/10)
WENN N hat mehr als 16 Bit
→ large_composite (σ = 1/15)
SONST
→ universal (σ = 1/10)

🎼 Harmonische Klassifikation - Ablauf

Überblick

Die harmonische Klassifikation (rsa/optimized_harmonic_lib.py) zerlegt N zuerst per Probedivision und benennt dann das Verhältnis der beiden Faktoren mit einem musikalischen Intervall. Sie verwendet eine 4-Stufen-Suche mit logarithmischer Oktaven-Reduktion; eine eigene Faktorisierung ist das nicht (Dok. 343).

Ablauf der harmonischen Klassifikation
  • 1
    Faktoren finden
    Klassische Faktorensuche mittels Probedivision bis √n.
    for i in range(2, int(math.sqrt(n)) + 1): if n % i == 0: return (i, n // i)
  • 2
    Verhältnis berechnen und Oktaven-Reduktion
    Das Verhältnis max(faktoren)/min(faktoren) wird berechnet und auf die Basis-Oktave reduziert.
    ratio = max(factors) / min(factors) while ratio >= 2.0: ratio /= 2.0 octave_shift += 1
  • 3
    Stufen-Vorhersage
    Aus dem größeren der beiden Faktoren und dem reduzierten Verhältnis bestimmt der Code die Stufe, mit der die Stufensuche beginnt; die höhere der beiden Vorhersagen gilt.
    if max_prime <= 17: prime_level = 1 # BASIS elif max_prime <= 31: prime_level = 3 # KOMPLEX else: prime_level = 4 # ULTRA if ratio >= 1.85: ratio_level = 4 elif ratio >= 1.60: ratio_level = 3 elif ratio >= 1.40: ratio_level = 2 else: ratio_level = 1 level = max(prime_level, ratio_level)
  • 4
    Hierarchische Harmoniesuche
    Zuerst prüft der Code einen Cache häufiger Verhältnisse und sucht dann innerhalb der Toleranzgrenzen über alle Stufen. Nur wenn das nichts liefert, durchsucht er die Stufen nacheinander, beginnend mit der vorhergesagten; die Toleranz wächst je Stufe um den Faktor 1,0 / 1,1 / 1,2 / 1,3.
    for level_idx in search_order: for ratio, interval in level.intervals: cents_deviation = abs(1200 * log2(target_ratio / ratio)) if cents_deviation <= tolerance * level.tolerance_factor: return SUCCESS(interval, cents_deviation)

Anteile je Stufe, nachgerechnet an allen 2624 Halbprimzahlen unter 10 000 (±50 Cent); sie folgen vor allem der Zahl der Zielverhältnisse je Stufe (10, 10, 15, 30):

BASIS (14,9 %)
Klassische musikalische Intervalle aus den Primzahlen 2, 3, 5: Einklang (1:1), Quinte (3:2), Quarte (4:3), große Terz (5:4) usw.
ERWEITERT (17,9 %)
Jazz und moderne Harmonien: natürliche Septime (7:4), 11. Oberton (11:8), 13. Oberton (13:8) usw.
KOMPLEX (21,4 %)
Spektralmusik und Mikrotonales: 29:16, 31:16, 25:16 usw.
ULTRA (45,8 %)
Xenharmonische Verhältnisse: 37:32, 41:32, 61:32 usw.; hier landen die meisten Verhältnisse großer Primfaktoren.

🔄 Optimierungen im Code

Grenzen-Filterung
Berechnung von Ober- und Untergrenzen für gültige Verhältnisse aus der Toleranz, um die Suchzeit zu reduzieren (harmonische Bibliothek).
Gecachte Berechnungen
LRU-Cache für häufige Oktaven-Reduktionen und logarithmische Distanz-Berechnungen mittels @lru_cache Decorator (harmonische Bibliothek).
Suchreihenfolge
Die harmonische Bibliothek beginnt mit der vorhergesagten Stufe. Die Ordnungssuche wählt σ nach Kategorie; das ändert das Ergebnis nicht.
Rationale Arithmetik
Die Ordnungssuche bewertet mit Fraction und ist dadurch bitgenau reproduzierbar (R65). Die harmonische Bibliothek rechnet Cent-Abstände in Gleitkomma.

🎯 Unterschiede der Ansätze

Ordnungssuche vs. harmonische Klassifikation

Ordnungssuche: Sucht die Ordnung von a modulo N und zieht daraus mit dem ggT einen Teiler; die Bewertung mit σ ändert das Ergebnis nicht.

Harmonische Klassifikation: Zerlegt N per Probedivision und ordnet das Verhältnis der Faktoren einem musikalischen Intervall zu.

Wann welchen Ansatz verwenden?

Um N zu zerlegen:
→ Ordnungssuche (Periodenfindung wie bei Shor) oder klassische Verfahren wie Pollard-Rho
Um das Verhältnis gefundener Faktoren zu benennen:
→ Harmonische Klassifikation
Für beides:
→ Erst zerlegen, dann benennen
