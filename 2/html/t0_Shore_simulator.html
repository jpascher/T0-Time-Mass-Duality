🧠 Was ist FFGFT?

FFGFT (Fundamentale Fraktale Geometrische Feldtheorie / T0-Zeit-Masse-Dualität) deutet die Quantenmechanik deterministisch; ein eigenes Faktorisierungsverfahren hat sie nicht (Dok. 190, R65). Dieser Simulator führt Shors Periodenfindung als klassische Ordnungssuche aus und zeigt zur Veranschaulichung ein Wellenfeld.

Die Grundidee: Der Simulator sucht die Periode klassisch. Er verwendet einen numerischen Suchparameter σ (Abtastheuristik, Dok. 190, R75). Der FFGFT-Geometrieparameter ξ = 4/30000 erscheint nicht in den Simulatorformeln.

📐 Veranschaulichung: Wellenfeld

∂²E/∂t² = (1 + σ)·∇²E + σ·V·E

Diese Wellengleichung dient nur der Visualisierung; sie ist keine FFGFT-Feldgleichung. σ beeinflusst nur die Wahl der Basis a, nicht das Verfahren der Ordnungssuche.

🚨 Browser-Begrenzungen — Warum die Ordnungssuche bei großen N versagt

WICHTIG: Die Ordnungssuche ist klassisch; ihr Aufwand wächst mit der Größe der Periode. Im Browser kommen praktische Limits hinzu:

1. Baby-Step Giant-Step (BSGS) — Speicher

BSGS benötigt O(√N) Speicher für die Baby-Steps. Für N = 10²⁴ (80 Bits) wären das 10¹² Einträge — das sind ~10 Terabyte RAM!

Browser-Limit: Wir begrenzen auf maxM = 1.000.000 → Das sind nur ~16 MB RAM.

Konsequenz: Perioden mit r > 10¹² werden NICHT gefunden.

📊 Erfolgsrate der Ordnungssuche

Nicht systematisch gemessen. Die Ordnungssuche verwendet eine einzige Basis; ist deren Ordnung ungerade oder ar/2 ≡ −1, findet sie keine Faktoren. Die Babyschritt-Riesenschritt-Suche ist im Browser auf 105 bis 2·106 Schritte begrenzt und findet daher nur Ordnungen bis etwa zum Quadrat dieser Schrittzahl. Für größere N die klassischen Verfahren (Pollard, Fermat) verwenden.

💡 Fazit: Die Ordnungssuche ist klassisch und im Browser auf kleine N begrenzt (siehe oben). Ein eigenes FFGFT-Faktorisierungsverfahren gibt es nicht (Dok. 190, R65). Für größere Zahlen ist der Fallback (Pollard's Rho) die beste Wahl.

🔧 Zwei getrennte Parameter

ξ = 4/30000 ≈ 1,333·10⁻⁴ ist der Geometrieparameter der FFGFT. Er ist fest und nicht einstellbar und hat keinen operationalen Bezug zur Faktorisierung.

Der Simulator verwendet intern einen numerischen Suchparameter σ. Dieser bestimmt die Abtastdichte bei der Periodensuche — er ist eine algorithmische Heuristik, keine physikalische Größe.

σ ist nicht der FFGFT-Geometrieparameter.

💡 Tipps für erfolgreiche Faktorisierung

  • Kleine Zahlen (N < 10⁹): Ordnungssuche ohne Fallback gelingt oft, aber nicht immer
  • Größere Zahlen (bis 253 ≈ 9×1015): Fallback "Alle Methoden" (Pollard's Rho, Fermat)
  • N > 253: wird von dieser Fassung abgelehnt
  • Primzahlen: Können nicht faktorisiert werden (mathematisch korrekt)
  • Semiprimes: Sind die besten Testkandidaten

🧠 What is FFGFT?

FFGFT (Fundamental Fractal Geometric Field Theory / T0 Time-Mass Duality) interprets quantum mechanics deterministically; it has no factorization procedure of its own (Doc. 190, R65). This simulator performs Shor’s period finding as classical order finding and shows a wave field for illustration.

The core idea: The simulator searches for the period classically. It uses a numerical search parameter σ (sampling heuristic, Doc. 190, R75). The FFGFT geometry parameter ξ = 4/30000 does not appear in the simulator formulas.

📐 Illustration: wave field

∂²E/∂t² = (1 + σ)·∇²E + σ·V·E

This wave equation serves only as a visualization; it is not an FFGFT field equation. σ only affects the choice of the base a, not the order-finding procedure itself.

🚨 Browser Limitations — Why the order finding fails for large N

IMPORTANT: The order finding is classical; its effort grows with the size of the period. In the browser there are additional practical limits:

1. Baby-Step Giant-Step (BSGS) — Memory

BSGS requires O(√N) memory for baby steps. For N = 10²⁴ (80 bits), that would be 10¹² entries — that's ~10 Terabytes of RAM!

Browser Limit: We limit to maxM = 1,000,000 → That's only ~16 MB of RAM.

Consequence: Periods with r > 10¹² will NOT be found.

3. JavaScript Engine Limits

  • Heap Memory: ~4 GB max (Chrome)
  • Stack Depth: ~10,000 recursive calls
  • Timeouts: Long-running scripts are terminated
  • BigInt: Multiplication of 10⁶-digit numbers is slow

📊 Success rate of the order finding

Not systematically measured. The order finding uses a single base; if its order is odd or ar/2 ≡ −1, no factors are found. The baby-step giant-step search is limited in the browser to 105 to 2·106 steps and therefore only finds orders up to about the square of this step count. For larger N use the classical methods (Pollard, Fermat).

💡 Conclusion: The order finding is classical and limited to small N in the browser (see above). There is no FFGFT-specific factorization procedure (Doc. 190, R65). For larger numbers, Fallback (Pollard's Rho) is the best choice.

🔧 Two separate parameters

ξ = 4/30000 ≈ 1.333·10⁻⁴ is the FFGFT geometry parameter. It is fixed and not adjustable and has no operational connection to factorisation.

The simulator uses internally a numerical search parameter σ. It determines the sampling density in the period search — an algorithmic heuristic, not a physical quantity.

σ is not the FFGFT geometry parameter.

💡 Tips for Successful Factorization

  • Small numbers (N < 10⁹): order finding without fallback often succeeds, but not always
  • Larger numbers (up to 253 ≈ 9×1015): Fallback "All Methods" (Pollard's Rho, Fermat)
  • N > 253: rejected by this version
  • Primes: Cannot be factored (mathematically correct)
  • Semiprimes: Are the best test candidates
